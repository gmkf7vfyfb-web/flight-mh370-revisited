**MH370 project review — 7 September 2026**

The reusable research is substantial, but the requested reliable, broadly supported MH370 trajectory posterior has not been achieved. A paper about reproducible evidence assessment and conditional sensitivity is plausible. A paper claiming a validated combined crash-location posterior is not supported by the present results. Publication suitability remains an editorial and scientific judgment, not something passing software tests can establish.

This review covered all 30 retrievable earlier threads in project proj_pm8k5krhiy, including hidden workers and threads labelled OLD. The archived-thread query returned none. I retrieved their retained logs and reviewed instructions, checkpoints, outcomes and relevant tool evidence against the current product and source bundles. The logs contain 492,000 retained events, 53,767 command-completion events and 537 context-compaction events; these are activity counts, not unique scientific experiments or billing amounts. One referenced antenna predecessor, thr_mbtt8qxrpj, returns HTTP 404. The old pre-refactor archive path cited in historical messages is not present in this environment, so some superseded work can only be assessed from its retained records. This is a project and scientific-readiness review, not a proof of every equation or a rerun of every historical experiment.

**Why work repeatedly stalled**

The record supports three explanations. First, sparse measurements constrain a very large space of possible flight histories: early restricted models were easier to sample, while the broad forward sampler repeatedly retains copies of a few lucky histories. More endpoint proposals can improve particle-weight statistics without exploring new past histories. Bridges, independent islands, replay moves, whole-history tempering and the older sparse-grid alternative have already been investigated; none establishes the requested full solution. The sparse-grid recovery also eventually failed coarse/fine agreement, rather than merely suffering an infrastructure problem.

Second, project control repeatedly substituted extensive machinery around the estimator for completion of the estimator. Historical threads document elaborate launch, receipt, hash and adversarial-validation systems before a decisive control ran, repeated optimistic delivery forecasts and a later release assembled from superseded one-turn artifacts. The Rust refactor was reported as about 9,189 lines; the current crates contain about 81,799 Rust lines including comments and in-file tests, with 11,119 in the broad-flight runner file alone. Growth is not itself a defect, but the current code no longer fits the original claim of a readily inspectable small inference path. Strong local tests and deterministic output do not by themselves establish statistical correctness on the actual problem.

Third, some interruptions were infrastructure failures: the dedicated bugfix thread locates oversized timeline pages, event-loop stalls and a watchdog restart cycle, aggravated by resource contention. It also records a real 12 GiB out-of-memory event and concurrent netCDF/HDF5 crashes. These account for interruption and rework, but not for the continuing statistical failure. This container currently has a six-CPU quota and a 12 GiB memory limit. There is no basis here for assigning a precise share of credits to model reasoning, context replay or numerical computation, or for concluding that changing model brand alone fixes the problem.

**A bounded decision, followed by a paper**

I recommend ending open-ended estimator escalation. If one final recovery attempt is worthwhile, give it **at most one focused engineering day and two hours of total numerical runtime on the existing six-CPU machine**. This is a spending limit for obtaining a decision, not a promise of a solution in that time. Use one implementation owner, one frozen scientific target and an independent numerical-methods review. Before another large run, a proposed sampling change must demonstrate why it addresses the already documented loss of past histories. Do not rebuild the surrounding framework or add further evidence modules during this proof.

The proof must exercise a tractable independent reference, synthetic flights and held-back MH371 positions with the same broad model, then compare independent seeds and increased computation. It must preserve repeated manoeuvres and control changes. Test posterior recovery/coverage and relevant distribution summaries, not merely that the known position appears somewhere in a large region. Existing diagnostic thresholds should not be relaxed to manufacture success, nor treated as calibrated physical laws. Failure at the cap means stopping this estimator development and proceeding with the narrower evidence/sensitivity paper.

If that proof succeeds, the sequence is: establish separate BTO-only and BTO+BFO trajectory distributions through 00:11; freeze a reproducible state/history handoff; propagate named end-of-flight/impact alternatives through the final transmissions; then add the requested drift families, Pléiades, gain, hydroacoustic and negative-search treatments one at a time. Each addition must respect common support, remove any already-used source prior, preserve dependencies and demonstrate that reweighting retains adequate sampling. Shared ocean forcing and image/recovery selection are not independent observations. Missing calibrations remain explicit conditional hypotheses or context; they cannot be made calibrated by additional CPU time.

The existing 11- and 16-minute suites make a **provisional one-to-three-hour numerical allowance** for an accepted core validation/production matrix reasonable to investigate, but its actual estimate must be measured on the successful sampler first. That allowance does not include developing missing acoustic/search calibrations or rerunning all multi-year drift models. For context, the September 6 expanded-debris run alone recorded 2,441 seconds, about 41 minutes. Reuse the existing audited inputs and separate surfaces wherever their limitations permit.

Allow **three to five focused working days to assemble a first submission-quality draft from accepted results**, reconcile stale claims, generate figures and reproduction instructions, and obtain author/scientific review; journal review and acceptance are additional and unforecastable. This is an editorial planning allowance, conditional on manuscript access and reviewers' availability, not an estimate for solving the current sampler. A fully calibrated all-evidence impact posterior has no defensible short completion estimate today. A transparent paper about conditional evidence and the limits of current inference does not need to wait for that outcome.
