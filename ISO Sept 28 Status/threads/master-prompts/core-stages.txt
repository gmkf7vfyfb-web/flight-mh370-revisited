D3. Hand-off at the stop epoch.

  - origin;
  - weight;
  - fuel, once the core adds it.
- Row-align the file the way history.npy is.
- Test: continuing from the hand-off reproduces a straight-through run for the same random streams, or document why not.

D4. End-of-flight stage (runner orchestration only; the science is in the end-of-flight module). For each hand-off trajectory, N children:
(a) The terminal module draws a hand-over time per child (e.g. flame-out) from its own model, using uniforms the runner supplies.
(b) The runner advances the child with the core flight dynamics to that time.
(c) The module integrates the descent to impact.
   - The atmosphere comes from the runner, as a service over the core's ERA5 grid. The earlier work needed up to about 60,000 ft and later than 01:00 UTC, so extend the grid if the module asks.
   - The module returns:
     - states at the requested SATCOM epochs (position, altitude, velocity including vertical);
     - the impact record;
     - a descent-family label;
     - a log proposal correction, so it can oversample descents near the measured values without biasing the result.
(d) The runner scores the selected 00:19 observations with the core SATCOM model:
   - BTO;
   - BFO, with the parent's Kalman bias.
   - Optionally, start-up-offset measurement alternatives. Port the quadrature idea from .archive/crates/satcom/src/final_bfo.rs into crates/satcom as an option. Pete questions the start-up-transient assumption, so it is one alternative among several: no offset, an offset model, inflated error.
(e) Every data option (none, R600 BTO, each BFO, both, …) is written from the same children as separate weight columns, so they can be compared side by side.
Output impacts.npy per replicate.

D5. A default terminal module, hypotheses/arc-kernel.
- Impact = the stop-epoch state plus a declared distance-from-arc draw. Tiny.
- It lets impact modules be exercised before the end-of-flight module exists.

D6. Impact hook, alternatives, composer.
- Evaluate impact_log_likelihood on impacts.npy for each enabled impact module and alternative. This should take seconds.
- Evidence sets come from config: e.g. "core", "core+drift", "all", or conditional on an alternative.
- Compute per-(replicate, mode) evidence increments so summary.rs pooling stays correct.
- Report ESS per factor and the posterior probability of each alternative.
- Align shared alternatives by name, and marginalise them jointly across modules (e.g. Σ_m P(m)·L_drift,m·L_pleiades,m).
- Trajectory-level alternatives run as separate strata, one filter per (mode, alternative), combined by prior × evidence. The core thread will add a per-particle guidance-plan hook on top of this after phase 1: plan(alternative, uniform) → Option<Plan>, where Plan is a plain serde struct the runner maps to flight::Guidance. Route families (N571, P627, LNAV to a destination, holding a track) become alternatives. particles_per_mode becomes per stratum: each alternative gets the per-mode allocation unless the config overrides it.
- Composed PDFs go on a 2-D equal-area grid in summary.json. Extend summary.rs (use its stats()/upper_edge); don't add a second summariser.
- Report pages are generic, driven by module metadata.

D7. A small cached fixture run: smoke scale, 00:11 stop, arc-kernel impacts. Add a make target to rebuild it, so module threads can test against it in seconds.
